# ourwed apply MVP 버전 브리프

작성일: 2026-05-13  
확정 커밋: `4d93eb8 Improve admin login and account details`  
Production URL: `https://apply.ourwed.in`

## 1. 버전 목적

이번 버전은 ourwed 지류 청첩장 주문 접수를 Google Sheets 기반 임시 수집 구조에서 Supabase DB 기반 운영 구조로 전환한 MVP입니다.

핵심 목표는 다음과 같습니다.

- 고객이 모바일에서 부담 없이 단계별로 신청서를 작성한다.
- 신청 데이터가 Supabase에 안정적으로 저장된다.
- 운영자는 관리자 대시보드에서 신청 목록, 상세 정보, 상태, 메모를 확인한다.
- 이후 관리자 추가, 상태 추적, CS 대응이 가능한 기반을 만든다.

## 2. 사용자 신청 폼

신청 폼은 단일 긴 스크롤이 아니라 6단계 페이지 이동 방식입니다.

1. 주문자 정보
2. 상품 선택
3. 예식 정보
4. 인쇄 문구
5. 배송 정보
6. 동의 및 접수

각 단계는 필수값 검증 후 다음 단계로 이동합니다.

  - 기본값 적용 버튼 제공
- 예식 관련 추가 정보

## 3. 데이터 저장 구조

Supabase를 사용합니다.

### 주요 테이블

- `applications`
  - 신청 기본 정보
  - 상품 정보
  - 예식 정보
  - 인쇄 문구
  - 배송 정보
  - 동의 항목
  - 상태값
  - `raw_payload`
- `application_accounts`
  - 신청별 계좌 정보
- `application_events`
  - 상태 변경 및 관리자 메모 히스토리
- `admin_users`
  - 관리자 접근 허용 이메일 목록

### 저장 방식 메모

핵심 조회 필드는 `applications`와 `application_accounts`에 정규화해 저장합니다.

추가 운영 필드 중 기존 테이블 컬럼을 늘리지 않아도 되는 값은 `raw_payload`에도 함께 저장합니다. 예를 들어 다음 값들은 관리자 화면에서 `raw_payload`를 통해 조회할 수 있습니다.

- 담당자에게 전달할 사항
- 배송 요청사항
- 은행 기타 직접입력값
- 예금주

## 4. 관리자 대시보드

관리자 URL:

```text
https://apply.ourwed.in/admin
```

### 로그인 방식

이메일 매직링크 방식은 제거했습니다.

현재 방식:

- 아이디: 관리자 이메일
- 비밀번호: Supabase Auth에 설정한 비밀번호

로그인 후에도 `admin_users` 테이블에 이메일이 등록되어 있어야 신청 데이터를 조회할 수 있습니다.

### 관리자 계정 생성

Supabase Dashboard에서 진행합니다.

1. `Authentication > Users`로 이동
2. `Add user`
3. 관리자 이메일 입력
4. 비밀번호 설정
5. 필요한 경우 이메일 confirmed 상태로 생성
6. 같은 이메일이 `admin_users`에도 등록되어 있는지 확인

### 대시보드 기능

- 신청 목록 확인
- 상태별 카운트 확인
- 이름, 연락처, 장소, 템플릿 검색
- 신청 상세 정보 확인
- 상태 변경
- 상태 변경 메모 저장
- 히스토리 확인
- 관리자 이메일 권한 등록

### 상태값

- 견적 안내
- 입금 확인
- 시안 작업
- 시안 확정

## 7. 현재 버전의 한계

- 템플릿 이미지는 아직 실제 청첩장 이미지가 아닌 플레이스홀더 스타일입니다.
- 신청 폼 제출은 클라이언트에서 Supabase RLS 기반으로 insert합니다.
- 관리자 계정 비밀번호 생성은 Supabase Dashboard에서 수동으로 해야 합니다.
- 일부 신규 선택 필드는 DB 컬럼 확장 대신 `raw_payload`에서 표시합니다.
- 고객용 신청 조회 페이지는 아직 없습니다.
- 결제, 견적서 발송, 이메일/SMS 알림 자동화는 아직 없습니다.

## 8. 다음 기능 검토: 모바일 청첩장 에디터

모바일 청첩장 에디터는 충분히 가능합니다. 다만 처음부터 Figma처럼 자유도가 높은 캔버스 에디터로 시작하기보다는, 운영 가능한 구조형 에디터로 시작하는 것을 권장합니다.

### 권장 방향

초기 버전은 “템플릿 기반 섹션 에디터”가 적합합니다.

고객은 자유 배치가 아니라 다음과 같은 섹션을 켜고 끄고, 순서를 바꾸고, 텍스트와 이미지를 수정합니다.

- 커버
- 신랑/신부 소개
- 초대 인사말
- 예식 일시
- 예식 장소
- 지도
- 갤러리
- 계좌 안내
- 참석 의사 RSVP
- 방명록
- 공유 버튼

이 방식의 장점:

- 모바일 화면 품질을 유지하기 쉽습니다.
- 고객이 편집하다가 디자인을 망가뜨릴 가능성이 낮습니다.
- 템플릿을 상품화하기 좋습니다.
- 관리자 검수와 운영이 쉽습니다.
- 빠르게 MVP를 만들 수 있습니다.

### 에디터 MVP 범위

1차 MVP는 다음 정도가 적당합니다.

- 모바일 청첩장 생성
- 템플릿 선택
- 텍스트 편집
- 이미지 업로드
- 섹션 ON/OFF
- 섹션 순서 변경
- 실시간 모바일 미리보기
- 저장/임시저장
- 공개 URL 생성
- 관리자 상세에서 모바일 청첩장 링크 확인

### 데이터 구조 초안

추가 테이블 후보:

- `mobile_invitations`
  - id
  - application_id
  - slug
  - template_id
  - status
  - theme
  - content_json
  - published_at
  - created_at
  - updated_at
- `mobile_invitation_assets`
  - image/video 파일 메타데이터
  - Supabase Storage 경로
- `mobile_invitation_rsvps`
  - 참석 의사 응답
- `mobile_invitation_guestbook`
  - 방명록

핵심 편집 데이터는 초기에 `content_json`으로 관리하는 것이 좋습니다. 섹션 구성과 필드가 자주 바뀌기 때문입니다.

### 에디터 UX 초안

화면은 2패널 구성이 좋습니다.

- 왼쪽: 편집 패널
- 오른쪽: 모바일 프리뷰

모바일에서는 한 화면에 하나씩 보여줍니다.

- 편집 탭
- 미리보기 탭

필요한 주요 컨트롤:

- 템플릿 선택
- 색상/폰트 프리셋
- 섹션 목록
- 텍스트 입력
- 이미지 업로드
- 순서 변경
- 미리보기
- 저장
- 공개하기

### 기술 구현 옵션

#### 옵션 A: 구조형 HTML 섹션 에디터

추천합니다.

- React 컴포넌트 기반
- 섹션별 JSON schema
- 프리뷰는 실제 모바일 청첩장 렌더링과 동일 컴포넌트 사용
- 유지보수 쉬움
- 빠르게 배포 가능

#### 옵션 B: 자유 캔버스 에디터

초기에는 비추천입니다.

- 드래그/리사이즈/레이어/반응형 처리 필요
- 모바일 최적화가 어려움
- 고객이 디자인을 망가뜨릴 가능성이 큼
- 검수/운영 비용 증가

#### 옵션 C: 하이브리드

중장기적으로 좋습니다.

- 전체는 구조형 섹션
- 커버 섹션이나 갤러리 일부만 고급 편집 제공

### 출시 단계 제안

#### Phase 1

- 관리자 내부용 모바일 청첩장 생성기
- 고객 대신 운영자가 편집
- 공개 링크 생성

#### Phase 2

- 고객이 직접 수정 가능한 편집 링크 제공
- 저장/미리보기/공개 요청

#### Phase 3

- RSVP, 방명록, 공유 통계
- 템플릿 판매/업셀 구조

#### Phase 4

- 고급 디자인 옵션
- AI 문구 추천
- 이미지 자동 보정
- PDF/이미지 내보내기
